## How We Work

We start with the objective, not the technology.

Projects are shaped around what they need to achieve, who they are for and how they will operate once released. The approach can differ between projects, but the same principles apply:

| Principle        | Approach                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| **Purpose**      | Define what the project needs to achieve before deciding how to build it.                                 |
| **Practicality** | Use appropriate technology, resources and processes rather than adding complexity for its own sake.       |
| **Ownership**    | Keep responsibility, access and project requirements clear throughout development and operation.          |
| **Quality**      | Test work properly and address issues before they become operational problems.                            |
| **Security**     | Treat security, access control and protection of information as part of development, not an afterthought. |
| **Continuity**   | Maintain, improve and adapt projects as requirements change.                                              |

Projects are expected to be useful in practice, maintainable over time and capable of evolving with the needs of Eldren Holdings and its associated ventures.

## Repositories

Repository visibility reflects the needs of the project.

A repository may be:

* Public
* Private
* Restricted
* Invitation-only
* Shared with authorised partners

Public visibility does not automatically grant permission to reuse, redistribute or commercially exploit project materials.

Unless stated otherwise, Eldren Holdings projects are proprietary.

---

## Working With Us

Contribution and collaboration are handled at project level.

Before contributing to a repository, review its documentation and check the applicable:

* Licence
* Contribution requirements
* Project agreements
* Security procedures
* Development standards

Access to a repository does not automatically mean that contributions are permitted.

---

## Security

Security issues should be reported privately.

Never commit or publicly disclose:

* Passwords
* API keys
* Access tokens
* Private keys
* Database credentials
* Confidential information
* Unreported vulnerabilities

Follow the `SECURITY.md` instructions provided by the relevant project.
